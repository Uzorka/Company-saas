MASTER DESIGN ARCHITECTURE
Company Management SaaS

ROLE
You are a senior product designer, UX architect, design systems specialist, and SaaS interaction designer.

Your job is to design the complete interface and user experience for a modern multi-tenant Company Management SaaS.

Do not write production application code in this stage.
Focus on product design, user flows, screens, states, interactions, motion, accessibility, and developer handoff.

PRODUCT SUMMARY
The platform contains two major experiences:
1. Public company website
2. Secure internal company management application

The system will initially serve one company, but the product must look and behave like a SaaS product designed for multiple companies later.

Each company has its own isolated workspace.

DESIGN DIRECTION
Create a premium, modern SaaS interface.

The experience should feel clean, calm, professional, fast, modern, easy to learn, app-like, and suitable for desktop and mobile.

Avoid cluttered ERP interfaces, excessive tables everywhere, oversized cards with little information, unnecessary gradients, excessive animation, overly playful styling, and generic admin-template appearance.

Use strong information hierarchy, generous but efficient spacing, clear typography, responsive data presentation, contextual actions, slide-over panels where useful, modal dialogs only where appropriate, progressive disclosure, meaningful empty states, skeleton loading, clear status colors, restrained motion, and compact mobile patterns.

ATTENDANCE UX
Employee check-in flow:
1. Employee opens dashboard
2. Taps Check In
3. System requests location
4. System shows current location status
5. Employee takes a live selfie
6. System records time, coordinates, location accuracy, office/remote classification, and selfie
7. Employee sees successful check-in state

Office attendance:
If the employee is within the company's configured office geofence, mark as Worked in Office.

Remote attendance:
If outside the configured geofence, mark as Worked Remotely.

The product must not imply continuous tracking.
Location is captured only during explicit verification actions.

Design exception states:
- location denied
- camera denied
- poor GPS accuracy
- no internet
- selfie failed
- outside expected location
- manual HR review
- already checked in
- check-out required

HR attendance view must show:
- employee
- status
- office/remote
- check-in time
- check-out time
- work duration
- selfie
- location
- GPS accuracy
- exception flag
- review state

FIELD VISIT VERIFICATION
Some tasks require proof that the employee visited a location.

Task verification modes:
- none
- photo only
- location only
- photo + location
- photo + location + report

For a verified field task:
1. Employee opens task
2. Taps Verify Visit or Complete Visit
3. App requests fresh location
4. App compares current position with target location
5. Employee takes a live photo or selfie
6. Employee adds visit report
7. System records location, timestamp, GPS accuracy, photo, distance from expected location, and report
8. Task becomes verified or flagged for review

Design:
- target location card
- current location status
- distance indicator
- verification badge
- evidence viewer
- exception state
- manager review state

RESPONSIVE REQUIREMENTS
Design desktop and mobile for every critical flow.
Do not simply shrink desktop tables on mobile.
Use cards, stacked rows, bottom sheets, mobile filters, sticky primary actions, compact navigation, and full-screen mobile forms where useful.

MOTION
Use motion to improve understanding.

Examples:
- sidebar transitions
- drawer opening
- tab transitions
- Kanban movement
- notification arrival
- success states
- check-in confirmation
- task completion
- pipeline stage movement

Avoid decorative motion.
Respect reduced-motion preferences.

ACCESSIBILITY
Design for:
- keyboard navigation
- readable contrast
- visible focus
- accessible forms
- clear errors
- screen-reader-friendly labels
- non-color-only status communication
- reduced motion
